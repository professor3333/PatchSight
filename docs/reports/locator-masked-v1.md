# Fix-commit locator: masked evaluation

Generated by `python -m patchsight.pipeline locator-eval`; do not edit by hand.

- **Sample `masked-v1`:** 200 vulnerabilities drawn with seed 20261118 from the 4,416 whose advisories link a GitHub fix commit (OSV snapshot `1de5d3c1dfe3…`). Each has one package, a fixed version, and fix commits on a repository its PyPI metadata declares.
- **Masked:** the locator never sees the advisory's references or git ranges. It reads the package's PyPI metadata, the repository's tags and the commits between the last vulnerable and the first fixed release.
- **Exact** means the located commit is one the advisories link. A fix backported to another branch, or split over several commits, counts as wrong if the linked one is not chosen, so the wrong-commit rate is an upper bound.

| Variant | Exact SHA | Wrong commit | Abstained | Lookups (median) |
|---|---:|---:|---:|---:|
| `baseline` | 9.0% (18; 5.8% to 13.8%) | 64.0% (128; 57.1% to 70.3%) | 27.0% (54; 21.3% to 33.5%) | 7 |
| `ranked` | 25.0% (50; 19.5% to 31.4%) | 47.0% (94; 40.2% to 53.9%) | 28.0% (56; 22.2% to 34.6%) | 7 |
| **Target** (the agent) | 70% or more | 5% or less | — | — |

Rates have Wilson 95% intervals. *Lookups* counts the GitHub and PyPI requests each vulnerability needs, answered from the cache or not. `baseline` is the proposal's: the first commit between the tags whose message says CVE, security or fix. `ranked` prefers a message naming the advisory's own IDs, then security words, then "fix".

## Wrong commits

| Variant | Wrong | A linked commit was between the same tags | It was not |
|---|---:|---:|---:|
| `baseline` | 128 | 98 | 30 |
| `ranked` | 94 | 64 | 30 |

In the first case the right commit was in view and another was chosen: a better choice could fix it. In the second, the comparison itself missed the fix, for example because it was made on another branch: only another search could.
